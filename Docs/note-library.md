# 笔记目录与周期管理

本说明对应 2026-09-20 确认后的私有更新需求。应用仍为花笺，沿用 React + Tauri + Rust、原编辑器、预览、主题和静态资源；没有 AI、自动生成、自动统计或 Flutter。

## 使用方法

- 侧栏目录名称用于选择目标，左侧箭头只负责展开／收起。
- 点击侧栏“笔记”标题返回全部笔记并选择默认位置，或选择自建目录后，点击标题旁的“＋”创建文件夹。输入名称后按 Enter，或再次点击“＋”确认；Esc 取消。可以输入 `学习/课程` 一次创建多级目录。
- 自建文件夹右键“重命名／移动文件夹”，可改名称并选择父文件夹。只能删除空文件夹；其中有未导入文件时也不能删除。
- 空白笔记及显式导入使用当前可写目录。系统周期目录不接收空白笔记，请先选择根目录、自建目录或磁贴目录。
- 原“新建笔记”菜单保留空白笔记、日记、周小结、月报。后三项先选择所记录的日期、ISO 周或月份，再创建或打开。
- 每日一篇日记、每周一篇周小结、每月一篇月报；重复点击打开已有笔记，不覆盖正文。
- 笔记右键“加入／调整周期管理”可为已有普通笔记登记周期，也可调整已有记录的周期。默认不移动文件、不改标题或正文；勾选后才移到标准归档目录。周期冲突时拒绝操作。
- 笔记右键“移动到文件夹”，或拖到可写目录，可以移动笔记。目录选择列表显示完整相对路径。
- 周期笔记移到自建目录后，同时可从实际目录和周期分组找到，仍然是同一个 ID、同一份文件；侧栏上层计数按 ID 去重。
- 快捷便签新建内容保存到磁贴目录。已有笔记钉住／取消钉住不会改位置。放进磁贴目录也不等于自动钉住。
- 普通笔记和磁贴按创建时间倒序排列，保存、改名和移动不改变创建时间。
- 点击“笔记”标题旁的刷新图标、打开目录、窗口获得焦点及启动时刷新；本版不使用常驻文件监听器。

## 侧栏与主题

- 侧栏标题为“笔记 / 筆記 / Notes”。不再显示额外的根节点；根下笔记和自建目录仍可直接访问，也可将笔记拖到标题来移回默认位置。
- 四个系统目录排在最前，与普通目录共用同一行样式。文件夹使用文件夹图标，文章使用文件图标和轻量列表行。当前文章用淡紫背景和细强调线标记。
- 日记显示“日记 → 2026年第38周 → 文章”，周小结显示“周小结 → 2026年09月 → 文章”，月报显示“月报 → 2026年 → 文章”。英文和繁体中文使用对应的时间分组标题。
- 隐藏日记和周小结中多余的年度显示层，不改真实归档路径。历史补记以记录日期显示和排序，不以创建日期代替；普通笔记和磁贴仍按创建时间排列。
- 展开箭头只负责折叠，不切换文章；文件夹名称选择创建位置。点击文章才加载内容。空目录选中后显示提示，无内容时不显示无效的展开箭头。
- 三语言标题和提示均来自 i18n。折叠、选择、拖拽和右键操作继续使用已有 API。
- 浅色采用 blog 的纸白、紫色、绿色和珊瑚色；深色采用深紫底色。主题通过共享颜色变量覆盖主窗口、设置、弹窗、编辑预览和跟随系统颜色的磁贴；用户自定义磁贴色保持不变。
- 主窗口四角为 11px，内部便签与磁贴圆角不变。自定义背景仍遵循已有背景图和遮罩设置，不附加新插画或视觉稿资源。

本次视觉改造验证与截图见 [视觉改造验收](ui-theme-validation.md)。

## 实际数据布局

Windows 默认数据位于当前用户“文档/花笺-RegulusApplEx”；不是旧 Release 的“文档/花笺”。自定义数据目录继续使用原设置入口。

```text
花笺-RegulusApplEx/
├── metadata.json
├── metadata.backup.json
├── notes/
│   ├── diary/2020/2020-W53/<id>_2021-01-01_日记.md
│   ├── weekly/2026/10/<id>_2026-W40_周小结.md
│   ├── monthly/2026/<id>_2026-09_月报.md
│   ├── tiles/<id>_便签标题.md
│   └── 学习/课程/<id>_笔记标题.md
├── images/<id>/...
└── backgrounds/...
```

- 磁盘根目录名固定为 `diary`、`weekly`、`monthly`、`tiles`，界面名称由语言包翻译。
- 日记按 ISO 周年／周归档；例如 2021-01-01 属于 2020-W53。
- 周小结按该 ISO 周的星期四所属的自然年／月份归档；例如 2026-W40 归入 2026/10。
- 月报按所记录月份的年份归档。
- 安装器只创建缺少的四个根目录，不创建笔记，也不覆盖已有数据。启动与切换数据目录后再次确保四个根目录存在。系统周期分支只有存在记录时才在侧栏显示。
- 不生成独立 reports 目录，不向 Markdown 注入隐藏格式或持续绑定。模板只是新建时复制的正文；现有笔记不会因语言切换而被改写。
- 主目录、系统根目录及自动归档结构不能通过文件夹管理改名或删除；自建文件夹不能使用系统保留名称。

## 实现分工

| 模块                                       | 职责                                               |
| ------------------------------------------ | -------------------------------------------------- |
| `src/features/noteTemplates`               | 原新建菜单、三语言模板及默认标题                   |
| `src/features/library/model.ts`            | 记录周期验证、标准归档路径、侧栏树和去重计数       |
| `src/features/library/NoteLibraryTree.tsx` | 目录选择／展开、笔记列表、移动入口与真实位置       |
| `src/features/library/LibraryDialogs.tsx`  | 周期选择／登记、文件夹改名／移动；提交锁和错误提示 |
| `src/components/MainWindow.tsx`            | 编辑器、保存守卫和管理入口集成                     |
| `src/components/NotePad.tsx`               | 新便签默认进入 tiles；复用普通笔记保存             |
| `src-tauri/src/services/notes/library.rs`  | 真实文件操作、全局周期唯一性、路径保护、索引恢复   |
| `src-tauri/src/lib.rs`                     | Tauri 命令及 notes-changed 通知                    |

原 `category` 字段现在保存以 `/` 分隔的相对目录路径。原有 `metadata.json` 每条记录增加可兼容缺省的 `recordType`、`recordPeriod`；没有这些字段的旧私有笔记仍视为普通笔记，不通过标题猜测类型。

Rust 在检查唯一性、创建／移动文件和发布索引期间持有同一进程级锁；多窗口通过同一个单实例 Tauri 后端操作。内容保存不再使用窗口缓存中的旧 category 移动文件，避免磁贴在目录移动后保存时把文件移回原处。

Markdown 修改使用同目录临时文件再替换；目录／笔记移动禁止覆盖目标，索引写入失败时尝试回滚移动。文件名保留稳定 ID 前缀。图片继续按 note ID 存放，标准图片引用不受目录变化影响。

## 文件边界与恢复

- 只有应用创建或显式导入的 Markdown 纳入管理。手工把未知 Markdown 放入 notes 不会自动导入。
- 已登记笔记在外部改名／移动后，只要保留文件名中的原 ID，刷新可在多级目录中匹配并更新实际路径。若有多个候选或 ID 被删除，不猜测归属、不覆盖文件。
- 外部修改已登记正文后，刷新更新摘要和字数，保留原创建时间。
- `metadata.backup.json` 是同结构的恢复备份。主索引损坏时先保留损坏原件，再从备份恢复已知记录、周期和创建时间；不会用文件修改时间伪造创建时间，也不会扫描未知 Markdown 重新认领。
- 索引及备份均损坏时，返回明确错误并保留 Markdown，需人工恢复备份。两者均不存在时建立空索引，已有未知文件仍需显式导入。
- 外部改名时请保留 ID；不要同时手工修改索引。删除索引及备份不等于安全的笔记导入方式。
- 多级路径拒绝绝对路径、`..`、Windows 保留名称、尾随空格／点，以及符号链接／junction 等重解析点。目录不能移入自身子目录。
- 遇到非应用管理的相对图片链接，移动会被拒绝并提示先导入图片或改为绝对链接；这是保护行为，不会静默损坏图片。Markdown 引用式图片采用保守检查，也可能需要先改成应用内图片引用。

## 构建与验证

开发工具仍为 VS Code；Windows 构建使用独立 Visual Studio Build Tools + Windows SDK，不需要完整 IDE。

```powershell
npm test
npx tsc --noEmit
npm run lint
$env:NO_PROXY = '127.0.0.1,localhost'
cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo fmt --manifest-path src-tauri/Cargo.toml --check
npm run build:windows
```

最终安装包与本机验收结果见 [本机验收记录](private-validation.md)。测试笔记放在工程内 `local-build/library-smoke-20260920`，不进入正式数据目录。未执行 Git 初始化、提交或推送。
